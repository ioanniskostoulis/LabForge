# LabForge interface profile

The profile contains the values specific to LabForge. The shared shell, tokens, geometry, motion, menu, Terminal, Help and message rules of the `GUIDELINES.md` of the pinned `forge-shell` apply unchanged and are not repeated. A value that is not decided is marked `to decide`, and a feature that LabForge does not have is marked `none`. The class and its commands are described in `FRAMEWORK.md`.

## 4. Workspace

| Field | Value |
|---|---|
| Centre views | The LaTeX editor (CodeMirror 6) with an optional PDF preview tile, closed when a report opens |
| Inspector sections | Builder and Files, both expanded |
| Folds that persist | None; both sections expand at every launch |
| Bottom tabs | Terminal, Plots, Tables, Messages |
| Default panel sizes | Inspector 246 px on the right; bottom panel 246 px; no override |

Builder holds Build PDF and Open PDF, the Name row, the builder (XeLaTeX or LuaLaTeX), Preset, Language, Bibliography and Preview PDF. The class controls read the `\documentclass[…]{.labforge}` line of `main.tex` and write it through the editor, so that undo reverts them; they are disabled when the line is absent. Files shows the report as one folder tree with a Show hidden files option.

The editor checks source 180 ms after typing pauses. This checks syntax, framework command keys and values, the bibliography option, and plain file arguments against the report's files without starting TeX. It marks the exact source range with a faint highlight and straight underline and puts marks in the optional minimap. Build PDF runs TeX once on request; its diagnostics retain file and line, with a command token when TeX supplies one. A warning that names an input line gets the file TeX was reading then, from the build log, so a warning inside an `\input` file points to that file. Build marks appear only when the editor still holds the text that was built and clear on the next edit. The last build error remains in the status bar after its transient message expires, until a successful build or cancellation. The PDF header shows Building, Build succeeded, Build failed with the last preview where available, or Preview out of date.

`mathpreview on|off` in Terminal, or Math preview in View › Editor, controls a local preview beside the cursor after a 300 ms pause in `\myformula`, `\myequation`, common math environments, or math delimiters. It starts off, does not build a PDF, and hides when the editor loses focus, the selection moves outside math, or the document scrolls. KaTeX renders supported expressions and `\ce`; unsupported commands such as `\qty` say why the quick preview is unavailable. The PDF remains the full TeX rendering.

On macOS and Windows, `commandlanguage on` in Terminal enables temporary English keyboard input after a backslash in the main editor. The previous input source returns after the character that ends the command name is inserted, including `{` or `[`, or when the editor loses focus. `commandlanguage off` disables this preference; it starts off. The change uses the system input source, not a character substitution. The renderer sends source-switch requests without waiting; Electron starts the switch before dispatching the backslash to the editor. On Windows the app selects an installed English keyboard layout for its window and restores the previous layout at the end of the command.

| Files tree rule | Behaviour |
|---|---|
| Order | Visible folders, visible files, then hidden entries, each by name |
| Hidden entries | Dot files and folders, including `.labforge.cls` and `.settings.tex`, plus LaTeX intermediates |
| Locked entries | `main.tex`, `.labforge.cls`, `.settings.tex`, `.labforge.json`, `.latexmkrc` and the standard folders cannot be removed or renamed; `data/references.bib` cannot be renamed, and the attempt is a warning in Messages |
| Content indicator | A pencil marks editable text and a crossed pencil marks read-only text. The lock badge separately means a required path |
| Context menu | File: Open (`Edit in LabForge` for `main.tex`), Show in Finder, Rename…, Move to Trash; an image, plot or table file also has Insert in editor; folder: Add files…, Show in Finder, Rename…, Move to Trash |
| External change | The working folder of a saved report is watched; a changed open text file is imported silently, or the user is asked when its editor holds edits |

The plots and tables panes are one component (`source/app/generator-pane.ts`): options on the left (a third to a half of the pane, at least 280 px) and Code and Preview tiles beside them. The look is provisional. In Tree view, a plot or table `.tex` file has a separate application-action group in its context menu: insert in editor, copy insertion command, copy default reference, and copy TeX source. The last action leaves out the generator settings comment.

Every standard item is built with the shell's `standardItem()` (the zooms with `zoomItems()`), so its label and key are the shell's. Help is the shell's `helpMenu()` with Writing helper added before Check for updates…. The update check reads the releases of `ioanniskostoulis/LabForge` (`identity.repository`); in the packaged desktop app **Update and restart** installs the DMG or the Forge setup through the shell's `registerUpdater`, and closes the window through the usual unsaved-report check first. At most once a day a newer release is noted in Messages.

Shortcut tiers: `tests/app/menu-definition.test.ts` runs the shell's `checkShortcuts` over the whole menu on both platforms, with and without a running build, with no exclusions. Build and Wrap text take app-tier keys (`appShortcut`); Build and Cancel build are one toggle, so Cancel build takes Build's key only while a build runs.

The editor options, the View › Editor menu and the Terminal commands read one catalogue, `source/app/editor-settings.ts`. Editor options are preferences and remain enabled on the welcome screen.

With Spell check on, the desktop editor marks misspelled prose after a short typing pause with a faint red highlight and dotted red underline. LabForge checks with its own English and Greek Hunspell dictionaries in `assets/spelling` (copied to `Resources/spelling`), shared by every report and identical on macOS and Windows; the operating system spellchecker is off. A word in Greek letters is checked as Greek and any other word as English, so mixed sentences need no markup; words in capitals are taken as abbreviations. The dictionaries load in a utility process the first time a word of their language appears. Right-clicking a marked word or pressing Shift F10 offers up to eight suggestions, closest first, then Add to dictionary (kept for every report in `spelling-words.txt` in the app's settings folder) and Ignore (until LabForge quits). LaTeX commands, comments, labels, optional keys, citations, file paths and math are excluded; an unclosed `$`, `$$`, `\(`, `\[` or math environment hides only the rest of its line, and closed math never runs past a blank line. Spell checking and source diagnostics scan text locally without starting TeX; Build PDF is the explicit TeX run. The browser preview has no desktop spelling bridge.

|---|---|---|

| View | Actual size, Zoom in, Zoom out | As above |

The welcome overview lists File (`new`, `open`, `recent`, `tabs`), View, Editor, Help and Console only; a document-only command answers `Open a report project first.` `panel` also takes `terminal`, `plots`, `tables` and `messages`. A bare `theme` reports the appearance, which the shared syntax does not yet accept. LabForge has no `autosave`: a report is written as it is edited, and only an untitled report waits for Save.
